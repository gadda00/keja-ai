Sessions last 12 hours, or 30 days with "remember me", refreshing on activity. Passwords are hashed on-device with PBKDF2-SHA-256 — never transmitted, never on any server.

Google Sign-In — active in production

The OAuth client 794306876985-…apps.googleusercontent.com is configured as NEXT_PUBLIC_GOOGLE_CLIENT_ID in Vercel (production, preview and development), so the real Google button already renders in the sign-in modal on keja.app. Sign-in verifies the Google ID token on-device (issuer, audience, expiry, verified email). The only optional step left: set NEXT_PUBLIC_ADMIN_EMAILS (comma-separated) to grant admin to specific Google accounts — the demo admin below keeps working either way. Runbook: docs/GOOGLE_AUTH_SETUP.md.

04 · The App
Install on Android & iOS

Keja installs as a full app from the browser — no store visit, ~10 seconds, works offline. The prompt appears automatically after a few seconds; the footer's "Install app" link opens it on demand.

Android — Chrome, Samsung Internet, Edge Tap Install app on the Keja banner (or browser menu → "Add to Home screen" / "Install app"). Confirm — Keja appears in the app drawer with its own icon and splash.
iPhone & iPad — Safari only Tap the Share button in Safari's toolbar → scroll to "Add to Home Screen" → tap Add. All 17 current iPhone/iPad splash screens are pre-baked, so the launch looks native.
What you get Full-screen standalone window, home-screen icon (with maskable adaptive icons on Android), offline shell with cached pages, long-press app shortcuts — Properties, Ask Keja, Deal Analyst — and automatic updates with a one-tap reload prompt.
Native shells (optional, for stores) The same build wraps in Capacitor for Google Play / App Store: npm run mobile:android / mobile:ios — see docs/MOBILE.md.
05 · Shipping
How keja.app stays live

Deployment is fully automated: push to main and the pipeline does the rest. Nothing manual stands between a commit and production.

Push to main github.com/gadda00/keja-ai — any commit triggers "Deploy to Vercel (keja.app)".
Quality gates run TypeScript strict typecheck → ESLint → 233 unit tests → static export with sitemap + service-worker version stamp. A red gate stops the deploy.
Vercel builds and serves Prebuilt static deploy to the keja-ai project; keja.app and www.keja.app serve it globally on the CDN edge.
Smoke test + watchers A post-deploy smoke test hits the live site; "Production check" then patrols hourly (manifest, service worker, headers), and Auto-Pilot refreshes listings every 6 hours.

Rollback in one minute

Vercel dashboard → project keja-ai → Deployments → open the last known-good deployment → menu → Promote to Production. No code changes required; the next push redeploys from source.

06 · Keys & Custody
Security and credentials

Nothing sensitive ships inside the site — the demo passwords above are QA fixtures, committed openly by design. Real credentials live in exactly three places:

CredentialWhere it livesWhat it does
VERCEL_TOKENGitHub repo secretAuthenticates the deploy workflow to Vercel
Vercel account accessvercel.com loginDomain, env vars, deployments, rollback
GitHub account & PATgithub.comSource control, Actions, releases

Rotate these two, now that the build works

A GitHub personal access token and a Vercel API token were shared during setup sessions. They served their purpose; storage in chat history is not custody. Rotate both — GitHub → Settings → Developer settings → Personal access tokens (revoke & regenerate), Vercel → Settings → Tokens (same). Then update the VERCEL_TOKEN GitHub secret once, and all future PAT-based pushes simply use the new value.

The site itself ships hardened defaults: a strict Content-Security-Policy with Google-Sign-In allowances, HSTS, X-Frame-Options DENY, nosniff, a locked-down Permissions-Policy, and valid .well-known app-association files for both platforms. The last Netlify chore: if the old Keja site still exists in the Netlify account, delete it (app.netlify.com → site → Settings → General → delete) — DNS already points at Vercel, this is purely hygiene.
